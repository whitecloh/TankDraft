# TankDraft — рабочий протокол
Last reviewed: 2026-09-12

## Источники и вход
Явные решения владельца → этот файл и .agents/project.md → регламенты → Docs/Features.
Начни с .agents/agent-context.md, затем читай только нужные контракты. Для чтения/поиска используй docs-scout; механические правки по готовому плану — mech-worker. Основной агент владеет решениями и проверкой результата.
Assets/ImmortalityLab/Docs — устаревший шаблон другой игры, не источник требований TankDraft.

## Выполнение
Перед изменениями: классификация, sensitive-check, ветка/dirty tree, состояние Unity/MCP, краткий план и способ проверки.
Согласованный локальный объём выполняй без повторных вопросов. Не ослабляй исходные критерии.
При открытом Editor сцены, prefabs, assets и тесты меняй/запускай через Unity MCP. Установка самого MCP через штатный UPM/CLI — разрешённое bootstrap-исключение. Batchmode рядом с открытым Editor запрещён.
Сохраняй чужие изменения, GUID и .meta. Не делай stash/reset, массовое удаление, force push. Рабочие ветки codex/* от текущей согласованной базы. Push/merge и внешние публикации — по явному поручению.

## Границы
Требуют отдельного решения, если не были явно включены в задачу: live-экономика и серверные настройки, миграция существующих сохранений, схемы аналитики, реальные покупки/публикации, необратимые операции и перезапись утверждённых решений.
Подключение SDK не разрешает публиковать live-конфигурацию. Секреты и машинные credentials не коммитить.
Проектные UI/prefab/config изменения через MCP разрешены в утверждённой задаче; прямая правка YAML — исключение с объяснением.

## Инварианты продукта
LeoECS Lite — боевое ядро; authored SO/каталоги → runtime data → подготовленные prefabs/pools.
Odin/Sirenix не использовать. UI не принимает боевые/экономические решения. Ряды и особые роли сохраняются.
Реальный PvP плюс боты при недостатке соперников обязательны. Полная мета входит в релиз.
Не подменять реализацию макетом, сетевую игру локальным ботом, проверку screenshot-ом или успехом компиляции.

## Документация и сдача
Русский язык; технические идентификаторы на английском. Детали фич в Docs/Features, история в Git.
Частые статусы в шапках фичевых документов. Рабочие логи/снимки в Logs (ignored) или вне репо.
В результате назвать изменения, проверенное, непроверенное и оставшиеся решения. Не утверждать, что runtime/устройство/сеть проверены, без соответствующего запуска.
