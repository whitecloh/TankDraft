## Текущий результат и проверка

- Было 12 meta-ID, из них 4 поддерживались боем. Теперь 13 playable battle-профилей (прежние 12 + инженер) и 2 служебных summon-профиля: `unit.drone_scout`, `unit.sentry_turret`. Все связаны с authored prefab; service-child не попадает в коллекцию/драфт. Старые 4 сохраняют исходный баланс и IDs. Новые значения — временные.
- Добавлены Passive/Melee, OpeningBacklineJump, RepairPulse, SpawnUnit/TTL. Инженер: каждые 5 с турель на 5 с, базовый cooldown 1/6 с, 50% **текущего** урона инженера с учётом его улучшения. Здоровье/дальность турели временные. Дрон носителя — наземная prototype-сущность; это ещё не доказанный аналог пчелы и не реализованная система полёта.
- `MatchService` и validation теперь принимают расширенный каталог, сохраняя 4 уникальных слота и требование трёх самостоятельных мобильных бойцов. Диагностический локальный бот копирует выбранные 4 ID; он больше не пытается взять весь расширенный каталог.
- `MatchPresentationTimings` и `MatchCardMotion` внедрены в реальный prefab карточки. Стабильный ключ `ChoiceToken` передаётся из обеих client session; вход слева направо не повторяется при каждом snapshot. Нажатие не ждёт завершения анимации.
- MCP authoring/validation: catalog, view catalog, draft settings, ability graph — PASS. Четыре новых диагностических сценария завершились в пределах диагностического watchdog 120 с; это **не игровой timeout**.
- Play Mode: все 13 playable и оба child ID прошли через `BattleWorldView`, количество view совпало со snapshot; 4 сценария по максимум 450 ручных fixed steps. Максимально создано 744 pooled views в диагностическом прогоне; это учёт объектов, не доказательство готовой оптимизации.
- Play Mode UI: entrance стартует, click отправляется один раз сразу, rebind того же offer не перезапускает motion, ширина LayoutGroup-слотов не меняется, Hide сбрасывает состояние. Для visual QA использован фактический prefab и Canvas 720×1600 из Match, с временными текстами; это не реальный сетевой драфт. Кадры: `Logs/ReferenceAudit20260915/draft-runtime-correct-canvas.png`, `engineering-runtime-v2.png`.
- Native: Server.Match **39/39**, ServerClient **126/126**, Persistence **18/18**. TRX: `Logs/ReferenceAudit20260915/Checks`. Во время промежуточного теста legacy fixture ошибочно требовал null abilities от всего расширенного каталога; исправлен на исходные 4 ID, добавлен отдельный JSON без Ability. Промежуточная Windows sharing race persistence прошла изолированно и в итоговом полном прогоне.
- Unity compilation successful; в заключительном Play Mode error log пустой; Editor возвращён в MainMenu/Edit Mode. Backend export `local-match.json` содержит 15 battle definitions; hash `0013d9df21de5a8ab848a374ce49f05d08adb7e19824c60d52143d967cc2e827`.

Существующие серверные билды не обновлялись автоматически. Новый инженер доступен для локальной диагностики; это не обещание его владения в существующем PlayFab-аккаунте.

## UI/UX и функциональная анимация

- Коллекция: выбор карточки → inline Info/Equip → Info открывает затемнённое окно; Equip показывает 4 стрелки над слотами армии. Нельзя заменить это прямой мгновенной заменой случайного слота.
- Окно информации V2 ~00:52 открывается быстро; нет основания назначать всем окнам один длинный bounce. Надёжно видимые анимации измеряются отдельно.
- Драфт: 1/3–3/3 и полоска времени; нажимается только актуальный выбор, переходы не продлевают deadline. Одинаковый ChoiceToken при очередном snapshot не перезапускает entrance.
- Экран результата V2 10:06–10:10: 4 участника, адресный mastery XP по очереди, частицы XP от общего визуального счётчика к карточкам, затем Continue. «Нажмите, чтобы пропустить» завершает только показ уже рассчитанной награды.
- Следом монеты/бонусы и возврат в меню; пак открывается отдельной последовательностью. Удвоение за рекламу — отдельная подтверждаемая операция, не локальное изменение счётчика.
- Панель общения/сдачи — отдельное окно поверх текущего состояния. Её открытие не останавливает матч.
- Главная: reward slots, валюты и навигация используют общие размеры/отступы/центровку; pulse/scale применяется внутри слота. Profile/settings, rank rules pager, pass scroll и cosmetic grid требуют отдельных состояний из UI_State_Map.md.
- При переоткрытии/смене окна motion отменяется и сбрасывается. Позднее получение уже завершённого раунда показывает актуальное состояние, а не принудительно проигрывает всю пропущенную цепочку.

## Реализация и порядок приёмки

1. Существующие 12 meta-ID получают боевые definitions, authored view prefabs и draft entries; исходные 4 сохраняют баланс. Призывные дочерние сущности не являются 5-м слотом армии. Отдельный инженер вводится локально только с полной связкой content → immutable definition → simulation → prefab; это не выдача в PlayFab.
2. Первый общий набор: Passive/Melee, начальный выход в тыл, ремонт, ограниченный призыв и TTL. Остальные строки таблицы не объявляются реализованными благодаря похожим снарядам. Тесты обязаны проверять реальные HP/target/spawn/outcome, serialization и ограничения поля/пула.
3. Драфт: authored MatchPresentationTimings, внутренний MatchCardMotion, стабильный OfferPresentationKey. Значения .25 с вход/.10 stagger близки наблюдению; .08 с press и scale .96 — временная настройка, не точное измерение видео.
4. Следующий боевой пакет: движущийся подрывник, токсичная зона/замедление и яд; затем shields/магазин/воздух/трансформация; сложный захват/ныряние — после устранения явно перечисленных неизвестных. Способности не включать как «готовые» до проверки зависимости от уровня/upgrade.
5. Следующий presentation-пакет: ожидание выбранной карты, последовательный spawn, Round/Fight, переход сердец; затем result XP/coins/pack и мета-окна. Текущий патч entrance не закрывает все эти пункты.
6. Приёмка PC: все доступные составы, смена состава/повторный бой, одинаковый seed → одинаковые snapshots; UI hide/rebind/click без дублей; визуальный прогон с плотной армией. Live progression и новые гранты остаются на этапе 2 общего плана.

3D-предложение отдельно: [ThreeD_Art_Pipeline.md](ThreeD_Art_Pipeline.md). Смена renderer/арены не подразумевается принятием этого аудита.
