# Локальный полный матч
Status: implemented; seeded exact-tie and Windows network scope validated
Last reviewed: 2026-09-13

## Запуск и границы

Открыть `Assets/TankDraft/Scenes/Frontend/MainMenu.unity`, включить Play и нажать «В бой». Также есть `TankDraft → Match → Open`: прямой запуск Match читает локальный профиль. Колода прототипа: мины, тяжёлый танк, ПТ-САУ, полевая САУ; поддержан приказ `order.reinforce_armor`. Неподдержанные выбранные типы/приказы дают сообщение с составом доступной колоды. Профиль не заменяется тестовым молча.

Это локальная вертикаль с явно подписанным ботом. Отдельная сцена сетевого боя реализована в Network_Match_Prototype.md; этот вход сохраняет локального бота. Матч не списывает энергию, не выдаёт награды, не меняет состав колоды и не записывает прогрессию. Остальные военные роли, приказы и мета остаются в релизном объёме.

## Реализованный поток

1. Армии пустые; каждый игрок получает три последовательных выбора из трёх карточек.
2. Добавление создаёт/пополняет стек; ×2 удваивает количество; UP увеличивает HP и урон всех экземпляров типа. Значения хранятся в конфиге.
3. Выбор приказа заменяет текущий обычный выбор. «Броня» усиливает HP армии только в ближайшем бою; второй заряд на уже действующее усиление не расходуется.
4. Обычный шаг применяется только после двух коммитов. До этого армия противника не меняется. Локальный бот выбирает по собственным предложениям до команды игрока.
5. После драфта запускается новая живая LeoECS-симуляция. View отображает состояния, снаряды, зоны и события; победитель заранее не вычисляется.
6. После раунда армия сохраняет количество и улучшения. В следующем раунде все юниты восстанавливаются с полным здоровьем.
7. Проигравшему последний раунд даётся один отдельный выбор из трёх, затем обоим три обычных. Общий счёт и серия поражений не меняют число бонусных выборов. Бонус бота применяется автоматически.
8. Четвёртая победа сразу переводит матч в финальный результат. Кнопка меню возвращает к мета-экрану.

Видеодоказательства правил: `Draft_Comeback_Reference.md`. Численный баланс ниже — экспериментальный военный прототип, а не восстановленная формула оригинала.

## Данные и зависимости

`MatchSettingsAsset` → immutable `MatchRules` / `MatchUnitDefinition` → authoritative local `MatchService` → `BattleScenarioDefinition` → `BattleSimulation` → snapshots/events → `BattleWorldView` / `UIMatchScreen`.

- `Runtime/Match/Domain`: чистый C#, assembly без Unity. Хранит счёт, армию, предложения, pending-коммиты и разовый приказ. `ChoiceToken` отклоняет старые и повторные команды внутри матча; результат раунда принимается ровно один раз.
- `Runtime/Match/Content`: настройки, тексты, ссылки на существующие боевые каталоги, мета-каталог и профиль. В каждом элементе драфтового каталога задана ссылка на BattleUnitAsset и количество пополнения. Значения копируются в доменные определения, SO не изменяются во время игры.
- `Runtime/Match/Presentation`: пассивные ViewModel, карточка и Screen с отдельными HUD/Draft окнами. Каноническая иерархия: UIMatchScreen → UIMatchHudWindow / UIMatchDraftWindow → UIPanel / карточки. LayoutGroup пересобирается при Bind/resize и отключается в idle. Три карточки — вложенные экземпляры одного prefab, размеры задаёт LayoutElement, раскладку HorizontalLayoutGroup.
- `Runtime/Match/Bootstrap`: VContainer scope, навигация и session. Передаёт immutable профиль между сценами, управляет ботом, lifecycle симуляции и биндингом View.
- `IMatchLauncher` в Shared/Contracts отделяет кнопку меню от реализации матча. `LocalProfileSettings` принадлежит Meta/Infrastructure; миграция сохраняет GUID и имеет MovedFrom.

`BattleArmyStack` получил опциональные проценты HP/урона. Прежние лабораторные сценарии используют нулевые модификаторы. Definition ID не меняется, поэтому тот же ViewCatalog и подготовленные prefabs обслуживают обе стороны с разной прокачкой. Боевые параметры не лежат в View и не переписывают исходные unit assets.

MatchService — авторитетное состояние локального матча, не объект для передачи целиком сетевому клиенту. Следующий PUN adapter должен выдавать игроку только его предложения/разрешённые публичные данные, отдельно валидировать match/session/actor identity и доставку команд. Текущий токен не является полной сетевой защитой.

## Конфиги прототипа

`Configs/Match/MatchSettings.asset` содержит 4 победы, 3 обычных выбора, лимит 12 экземпляров одного типа, UP +15% HP / +12% урона, 3 заряда брони по +25% HP и веса Add/×2/UP = 60/28/12. Базовое пополнение: мины +2, тяжёлый танк +1, ПТ-САУ +3, САУ +1. Вес применяется к допустимым кандидатам; три карточки представляют разные типы техники.

Чтобы армии из одних одноразовых преград не создавали незавершающийся бой, последний обычный выбор при отсутствии самостоятельного бойца предлагает три типа стреляющей техники. Признак CanFightAlone выводится из MoveSpeed и Attack авторского BattleUnitAsset; строковых сравнений с названием мин в домене нет. Это явное ограничение стартового контента, не правило, доказанное видео. Приказ доступен после появления подвижного бойца и только в обычном драфте; применение приказа в бонусном выборе пока не восстановлено по референсу.

Нет игрового лимита времени, сравнения HP или принудительного победителя. Outcome использует точнейшее время попаданий/смертей; при точной одновременной гибели последних армий authority/local authoritative simulation один раз выбирает seeded random winner и сохраняет seed trace с общим результатом. Локальный клиент не делает независимый roll. 40 матчей / 219 раундов завершены без `ReviewRequired`, включая 3 seeded exact ties; 4 старых `ReviewRequired` остаются historical evidence предыдущего поведения.

## Проверка

Команды из корня: `Tools/Match/invoke-match-check.ps1 -Action Validate`, `-Action PlayMode`, `-Action Open`.

- Доменная проверка: 13 групп assertions на барьеры, устаревшие/некорректные команды, камбэк, приказы, немедленный финал, ReviewRequired и ошибочную колоду; этот historical result предшествует новому tie rule.
- 40 seeded прогонов, 202 боевых раунда: 36 матчей завершены, 4 остановлены для проверки одновременного результата. Это прежнее evidence для `ReviewRequired`, не validation нового seeded tie rule. Максимальная длительность раунда 18,10 с. Watchdog теста не назначает игровой исход.
- Editor Play Mode: PASS 62 assertions; полный семираундовый матч, результат 3:4, запуск из меню, три карточки, приказ, бой, возврат, неизменный файл профиля и teardown без Unity errors. Проверяются target size/bounds Game View 576×1280 и 576×1024, не Scene View 971×602.
- Prefab validation подтверждает общие вложенные карточки и LayoutGroup. Снимки находятся в ignored `Logs/TankDraftSetup/MatchQA`.

Это собственный Editor harness, не Unity Test Runner, Android/iOS, touch QA или проверка сетевой синхронизации.

Регрессии после переноса: прежняя лаборатория прошла три парных сценария симуляции; меню — 264 проверки prefab/binding, профиль — 38, меню в Play Mode — 31. Итоговый аудит: 199 собственных assets, 39 prefabs без отсутствующих scripts/references, 149 исходных GUID сохранены. Editor оставлен в чистом MainMenu, вне Play Mode, без compile errors.
