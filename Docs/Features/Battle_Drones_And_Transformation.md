# Дроны носителя и осадная трансформация
Status: implemented; native + Unity Play Mode + joint PC Fusion smoke passed; owner visual/remote acceptance separate
Last reviewed: 2026-09-16

## Решения владельца

- Покупаемый юнит — наземный танк-носитель. Отдельного воздушного юнита не добавляем.
- Выпущенный дрон не имеет HP, не получает урон и не удаляется при гибели носителя. Летит к цели, наносит один удар и исчезает.
- Трансформация полностью лечит: 50/100 превращается в 400/400. Один раз за раунд, у живого юнита; не воскрешает.
- Из референса: задержка 10 секунд, максимум HP ×4, урон ×3, ближняя атака по области. Остальные численные значения временные и находятся в конфигах.

## Данные и исполнение

`BattleProjectileAsset → BattleProjectileDefinition → BattleSimulation` задаёт скорость, радиус, область попадания, зону и `RetargetOnTargetLost`. Носитель использует `projectile.drone`, его прежний SpawnUnit отключён. Старый support asset `unit.drone_scout` сохранён для совместимости ссылок, не покупается и носителем больше не создаётся.

Дрон хранит сторону, урон и эффекты попадания при запуске. После запуска симуляция не требует живого носителя. Временно при потере цели выбирается ближайший живой враг; при равной дистанции — минимальный стабильный Id. Это переключается в конфиге снаряда; прежние снаряды по умолчанию сохраняют старое поведение. Правило завершения раунда не менялось: дроны не продлевают раунд после уничтожения армии.

`BattleUnitAsset` содержит включение трансформации, задержку, проценты HP/урона и радиус атаки. `unit.siege_transformer` — наземный ближний юнит с приоритетом расстановки 850. Начальные характеристики с учётом улучшений масштабируются один раз. Трансформация сохраняет текущие кулдауны и щит, меняет HP/урон/область атаки; физический радиус остаётся прежним.

Сервер передаёт `TransformationStage` (0/1). `BattleEntityState.WireVersion=3`: Capture, binary codec/hash, строгий JSON, native Fusion и клиентские проекции. Неполный или старый snapshot отклоняется. Клиент не определяет трансформацию своим таймером. Совместно обновляются authority, gateway и клиент; старые сборки не смешиваются. Existing replay build guard продолжает защищать несовместимые журналы, миграция сохранений не выполняется.

## Где настраивать

- `Assets/TankDraft/Configs/Battle/Units/Unit_DroneCarrier.asset`: урон, частота выстрелов и прочие характеристики носителя.
- `Assets/TankDraft/Configs/Battle/Projectiles/Projectile_Drone.asset`: полёт и поведение при потере цели.
- `Assets/TankDraft/Configs/Battle/Units/Unit_SiegeTransformer.asset`: трансформация и базовые характеристики.
- `Assets/TankDraft/Configs/Battle/Presentation/BattleViewCatalog.asset`: prefab, visualScale, visualOffset, transformedVisualScale для каждого определения.
- `Assets/TankDraft/Configs/Battle/Presentation/BattlePresentation.asset`: длительности появления, перестроения, вспышки попадания и трансформации.

Подготовленные примитивы используют существующие пулы. При обычной трансформации размер плавно меняется, при восстановлении уже трансформированного юнита сразу отображается текущее состояние. Возврат в пул сбрасывает стадию. Новая модель заменяется ссылкой в каталоге; боевые числа не требуют правки prefab.

Новый юнит добавлен в authored meta/draft/catalog, но это не выдаёт владение существующим PlayFab-аккаунтам и не публикует live-каталог. Новые покупки/экономика в этом патче не включались.
