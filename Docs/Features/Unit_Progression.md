## Правила

Основание — `Reference_Progression.md`: мастерство, уровень техники и фрагменты конкретной техники — разные сущности. Владелец разрешил временные числа для скрытого баланса. Источник чисел — `Assets/TankDraft/Configs/Meta/Progression/progression-rules.json`; сервер получает одинаковый экспорт `Backend/Content/progression-rules.json` с SHA256. `BalanceStatus` прямо помечает временные значения.

- Четыре участника победного боя получают по 10 mastery XP; временная награда за поражение — по 5. Состав, XP и версия правил фиксируются вместе с завершённым результатом, без выбора получателя клиентом.
- Фрагменты принадлежат конкретной технике. Улучшение уровня тратит её фрагменты и CO. Пак выбирает три разные доступные принадлежащие игроку единицы техники независимо от состава армии; сервер сохраняет результат случайного выбора до валютного вызова.
- Мастерство растёт от боя, отдельного boost за mastery chip либо покупки следующего порога за GM. Это не общий свободно распределяемый battle XP.
- Пороговые награды мастерства забираются отдельным серверным намерением; битовые/чиповые награды сохраняются в progression, CO — в Legacy wallet. Статистические бонусы уровня/мастерства фиксируются при входе в очередь отдельно для каждой стороны и складываются с усилениями драфта. Исходные определения техники не изменяются.
- Монеты за бой остаются отдельным durable settlement R3.2. Действующая закрытая QA-политика **1 CO / максимум 10 выдач на аккаунт не менялась**. Показанные в видео 500+70 и 700+56 задокументированы, но не активированы как новая политика.

## Данные и границы

`tankdraft_profile_v1` продолжает хранить существующий профиль/армию; Inventory и CO/GM остаются PlayFab Legacy. Новый отдельный Entity Object `tankdraft_progression_v1` содержит уровни, unit bits, mastery XP, chips и полученные milestones. Запись через ExpectedProfileVersion/CAS; ошибка чтения не сбрасывает данные.

Серверный `ProgressionService` выполняет намерения UpgradeUnit, BuyOffer, BoostMastery, BuyMasteryLevel, ClaimMilestone. Gateway привязывает их к authenticated account, проверяет instance/content, не принимает account/цену/количество выдачи от клиента. Изменение progression во время очереди/матча запрещено. Client проверяет версию правил и идентичность receipt операции.

Флаг `ProgressionEnabled` в приватном `playfab-legacy-meta.json` по умолчанию false. На текущих тестовых аккаунтах он остаётся выключен. Код и тесты не создавали облачную экономику, не добавляли валюту/предметы, не меняли billing, Azure, TitleData или существующие профили.

## Восстановление операций

Журнал `fusion-progression/operations.sqlite` находится вне репозитория и имеет exclusive writer lock. Это один авторитетный процесс, не распределённый backend. Состояния Prepared → ProfileApplied → WalletSending → Completed; неопределённый валютный ответ → NeedsReview.

Для покупки сначала сохраняется право на предмет/улучшение, затем один раз вызывается Legacy списание. Это сознательный компромисс в пользу игрока: при сбое возможно бесплатное улучшение; списание без сохранённого предмета не допускается. CAS после потерянного ответа проверяет sequence/fingerprint; более новое состояние не перезаписывается. Неопределённый ответ Legacy нельзя слепо повторять.

Валютный запрос после durable WalletSending использует собственный серверный тайм-аут 10 секунд: отключение клиента не отменяет уже начатую операцию. На перезапуске WalletSending переходит в NeedsReview. Новые покупки аккаунта блокируются до разбора; battle XP может продолжать начисляться. Клиент хранит unresolved intent и Guid на диске в scope аккаунта, стабильном между перезапусками сервера. Подтверждённый отказ до начала операции очищает intent; потеря ответа сохраняет его.

Операторский вход выполняется при остановленной authority:

```powershell
& '.\Logs\BackendSdk\dotnet.exe' '.\Backend\TankDraft.RemoteHost\bin\Debug\net10.0\TankDraft.RemoteHost.dll' --review-progression list
```

Действия: `ConfirmApplied`, `ForgiveDebit`, `CompensateCreditOnce`, далее QA-index, operation-id в формате N, ссылка на доказательство; без `--apply` только просмотр намерения. ConfirmApplied требует внешнего доказательства исполнения. ForgiveDebit оставляет игроку предмет, закрывая спор без нового списания. CompensateCreditOnce допускает ровно одну компенсирующую выдачу CO/GM; её попытка атомарно фиксируется до HTTP. Повторная неопределённость требует подтверждения факта выдачи, автоматического третьего запроса нет. Публичного операторского API нет, ключ не выводится.

## Клиент

Подготовленный `UIProgressionWindow.prefab` подключён к UIRoot. Четыре карточки — HorizontalLayoutGroup; кнопки — VerticalLayoutGroup. MainMenuStartup связывает сервисы/каталог/presenter, view не вычисляет цены и награды. Из карточки техники открывается прокачка, из магазина — предложения. После покупки пака отображаются выбранные сервером единицы и их текущие bits. Завершённый бой показывает страницы mastery → CO → меню; история позволяет открыть результат повторно. Локальная отметка просмотра влияет только на показ окна.

### Обновление 15.09: жизненный цикл UI

`UIProgressionWindow` имеет authored UI Id `main_menu.progression`. Редакторская проверка инстанцирует полный `UIRoot`, выполняет `UIRegistry.BuildMap()` и требует, чтобы этот Id указывал на окно прогрессии: так проверяются как отсутствующий, так и дублирующий Id до запуска игры. В teardown кнопки и их корневые GameObject могут уже быть уничтожены при выгрузке сцены; `Release` учитывает Unity fake-null и не обращается к уничтоженным ссылкам. `ValidateReferences` при обычном `Bind` намеренно не ослаблялся.
